# World generation, distant terrain and weather acceleration

> **Status note (2026-10-19).** This audit was written while the pack still pinned Distant Horizons (the Forge
> 1.20.1-era LOD mod). Distant terrain is now drawn by Infinite ATLAS ([ATLAS.md](ATLAS.md)), which consumes Java's
> authoritative heights instead of a second generator, so the DH and Voxy points below are history. The CPU-side
> findings (region stencil, one authoritative terrain batch contract, exact-bit parity) still apply.

Audit date: 2026-10-18. This records source/API inspection and a small exact CPU optimization. It does not claim a GPU terrain generator or a measured frame-rate improvement. The coordinated client/server build and visual pipeline remain the acceptance path in [LIVE-WORLD-PREVIEW.md](LIVE-WORLD-PREVIEW.md) and [WORLD-TESTING.md](WORLD-TESTING.md).

## Upstream compatibility checked now

The official [C2ME release notes](https://github.com/RelativityMC/C2ME-fabric/releases) describe a density compiler, OpenCL C backend, scheduler work, aquifer acceleration and serialization improvements. These are useful architectural leads; upstream throughput numbers are not NirnCraft measurements.

The official [C2ME OpenCL module](https://modrinth.com/mod/c2me-ocl) currently accelerates noise and biome stages, requires Java 25 and OpenCL 1.2 with FP64, and lists Fabric/NeoForge releases for 1.21.1 and newer. It explicitly excludes custom density functions. Its documented DH path requires DH 3.3+ with `Internal Server` / `Full - Save Chunks`. NirnCraft's Forge 1.20.1, Java 17 and three custom density functions prevent treating that as a compatible install. The [license manifest](https://raw.githubusercontent.com/RelativityMC/C2ME-fabric/dev/26.3.0/LICENSE.md) separates the MIT code from the proprietary OpenCL module. An independently written backend can use the ideas; this is not permission to copy that module.

The [unofficial Forge 1.20.1 port](https://github.com/udbwhdjwbdj/c2me-opencl-forge1201) describes reverse-engineered research code, with distribution restrictions on its accelerator parts. It has not been installed or validated here, and its interception approach would also need reconciliation with this repository's no-mixins rule.

[Voxy's official page](https://modrinth.com/mod/voxy) lists Fabric and an OpenGL 4.6 requirement, requires explicit shader support, and does not offer Forge 1.20.1. It also excludes unofficial backports from its pack permission. Its compact LOD conversion and batching are research leads, not a reason to replace the working DH integration without compatibility and visual evidence.

[DH's official page](https://modrinth.com/mod/distanthorizons) supports the current older Forge generation and describes GPU rendering plus server/client LOD delivery. A local `javap` inspection of the actual pinned 3.3.3 jar additionally confirms `DhApi.worldGenOverrides.registerWorldGeneratorOverride(level, generator)` and public `IDhApiWorldGenerator.generateChunks`, `generateApiChunks`, and `generateLod` methods, with vanilla-chunk, API-chunk and API-data-source return types. Those are a possible extension boundary; the current NirnCraft integration does not use it. The remote developer wiki was unavailable during this check, so interface signatures are verified against the pinned binary rather than assumed from newer documentation.

## Ranked implementation path

1. **Measure the whole critical path and keep readiness strict.** Use the same seeds, routes and stopped saves before/after. Record plan loading, terrain/biomes, structures/features, lighting, packet delivery, native mesh build/upload, DH generation/conversion/upload, shader compilation, first useful view and fully settled view separately. Existing worker timings and DH data samples are useful partial probes, not end-to-end completion. Repeated captures require public native busy/upload/render-frame and lighting checks. Do not reduce distance or call incomplete terrain a pass.

2. **Remove identical CPU work first.** The region-stencil change is the first bounded implementation. Its independent former accumulation path produces identical bytes for all 13 climate inputs over 40 changing snapshots, including missing-neighbour fallback. The test reduces 360 repeated geographic reads to nine cold reads and 351 hits. Additional tests cover negative coordinates, distant slot reuse, world/resource identity changes and late arrival of dynamic climate. Benchmark actual near/far worker milliseconds, allocation/GC, presentation/upload time and cold-start cost before claiming a gain. The cache does not change samples, resolutions or weather cadence. Next static-cache candidates require their own profiles and equality checks; wind-dependent orographic probes cannot be cached as fixed values.

3. **Create one authoritative terrain batch contract.** Extract batches through public NirnCraft density/planner APIs, not a second approximate height generator. An immutable batch should identify seed, dimension, generation/data/plan revision, coordinate bounds, sampling schema and backend. It can share immutable map/region/hydrology inputs with weather and exact density results with chunk generation. Full chunk results may be offered to the public DH generator API only after final blocks, caves, water, structures and surface paint exist. A top-surface raster alone loses overhangs, caves, bridges and buildings. Keep edited/player-built chunks authoritative. Bound memory and outstanding jobs; invalidate old futures/results on world, reload and generation changes.

4. **Build an independent, disabled-by-default GPU density prototype.** Start with an owned batch of map channels and density evaluations exposed through public `fillArray`/planner entry points. An offline tool may create larger batches to find the crossover point; it must call or compare against the real Java implementation. Keep plan masks/protected caves/islands/hydrology and seeded noise semantics. Probe actual device/driver/FP64 support, compile kernels once per compatible code/data/device key, batch transfers, and measure host packing, kernel, readback and synchronization separately. Java 17 compatibility and optional native-library deployment need an explicit implementation. FP64 alone is not proof of bit equality: control contraction, operation order, division and transcendental differences; compare full outputs, retaining the CPU path whenever parity or supported hardware is unproven. A narrow threshold fallback requires a justified error bound, not a guessed epsilon. No world mutation or GL work from unowned worker threads.

5. **Connect proven output to DH, then prioritize the visible backlog.** Prototype a per-level public generator override in a disposable world, feeding complete authoritative batches. Check cancellation, edited chunks, save/reload, custom dimensions, API version changes, exception recovery and shutdown. Measure whether DH conversion or upload has become the new bottleneck. Investigate coarse-to-fine scheduling only through supported APIs, preserving eventual geometry and checking silhouette/water/lighting seams while refining. A custom DH override is not automatically a GPU shortcut; compare it with DH's existing vanilla-chunk route first.

6. **Share static landscape inputs with weather before moving its dynamics.** Region, height, slope, water and terrain masks can share immutable source data without pretending weather cells and terrain voxels have the same resolution. A later GPU weather backend must preserve field equations, precision, cadence, server authority, lightning/fog consumers and epoch ownership. Moving only the client model creates a synchronization/readback problem because common/server logic still needs weather values. Benchmark actual GPU contention with dense clouds, snow/sand/ash storms and Helgen smoke. Faster idle GPU kernels are not sufficient if game frame times get worse. Full fluid transport, SDF skipping and temporal cloud history remain separate visual research projects with motion/disocclusion tests.

## Acceptance evidence

Each backend needs hashes of final block states, biomes, heightmaps, fluids, structures and protected road/town/dungeon outcomes against the authoritative CPU path across region borders, ocean wrap, steep mountains, water crossings and large underground spaces. Test multiple seeds and generation orders, cold/warm caches, reload, server/client dimensions, limited memory, no compatible GPU and cancellation. Do not certify full output using a few density samples.

For performance, compare at least paired warm runs and explicit cold-start runs with source/build/driver/save/settings identities recorded. Keep storage, Java warm-up, shader compilation and compute changes separate. Report median and tail completion/frame times, server MSPT, CPU load, GPU busy time, memory and transferred bytes. The same shader preset, resolution, distances, weather and routes must be used. Capture real in-world views with and without shaders after terrain readiness; repeat moving flight and cave traversal, DH/native seams, storms and heavy fire. No sample-count, effect-source or resolution downgrade is part of this plan.

The existing storage experiment used the same stopped 71.3 MB save and unchanged sources in sequential F/E/E/F runs. Its warm-pair medians were total regeneration 61.5 s on F versus 53.9 s on E, saving 2.1 versus 1.3 s, and generation 37.1 versus 37.7 s. That supports an I/O investigation, not faster density evaluation. All four corridor acceptance runs still failed their independent road checks; completed regeneration was recorded separately. Raw evidence is `dist/weather-review/storage/world-20261017T224937Z/benchmark.json`; the first F boot included warm-up and is not a fair boot-speed comparison.

This phase adds no GPU mod, custom GPU backend, DH generator override or quality setting change. The exact region cache is the only new performance implementation in this audit. The coordinated full build passes; paired runtime benchmarks and end-to-end gains remain pending. Ocean-loop runtime evidence is retained separately under `dist/code-review/ocean-loop/`, including failed capture attempts rather than silently discarding them.
