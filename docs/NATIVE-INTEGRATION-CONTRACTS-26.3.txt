Skycraft data contracts for the external native visual integration
Baseline: Minecraft 26.3 / NeoForge 26.3.0.90 / Java 25

This handoff describes existing data entry points. It does not certify the new
external lighting/shader/distant-visual mod, enable preserved legacy integrations,
or transfer ownership of Skycraft's authoritative gameplay simulation. No new
cross-mod snapshot facade is implemented by this document.

Ownership and threading

Skycraft owns weather decisions, regional climate, terrain/settlement plans,
dungeon metadata, spell gameplay and persistent player/world data. The external
mod owns its rendering implementation. Consume data without advancing weather,
forcing terrain loads, changing server clocks or editing saved plans to render.

Server state is sampled on its owning server thread. Current client weather and
interior state are sampled on the client game/render thread. ClientWeather.fronts
returns detached front objects, but creating that snapshot iterates a mutable
client list: its existing "thread-safe snapshot" comment does not authorize
calling it concurrently from a worker. Create the copy on the client thread,
then pass immutable values to workers. Do not mutate returned live front objects
from sampleFront/nearestApproachingFront.

Use actual level identity, dimension Identifier and a session/resource generation
token for asynchronous work. A matching seed or dimension string alone does not
identify the same loaded world. Discard old jobs/results on disconnect, world
replacement or relevant resource reload. Do not retain a prior level's registry
provider or publish a worker result into whichever world happens to be current.

Units and identities

Positions/heights/radii/distances use Minecraft world blocks. WeatherFront velocity
uses blocks per game tick, and ticksLeft uses game ticks (normally 20 per second).
World X/Z coordinates retain their signs; north is negative Z. Tamriel sea level
is 63. Native Level.getMinY/getMaxY are inclusive bounds; getMaxY()+1 is exclusive.
Use dimension.identifier() and native net.minecraft.resources.Identifier.

Clock time for phases/calendar is Level.getDefaultClockTime(); Level.getGameTime()
is elapsed simulation time. Native dimensions may use fixed clocks/environment
timelines. Solar angle is not interchangeable with elapsed game ticks. Existing
client SkyEnvironment.sunCycle/starBrightness query the native environment and
timelines; do not infer every dimension's sun from an overworld-only clock formula.

Use Region.id(), WeatherKind.id() and dimension identifiers in external saved
metadata. Raster region indices and enum ordinals are implementation encodings.
Existing WeatherKind wire ordinals are append-only; changing their order changes
the interpretation of already synchronized and persisted weather values.

Weather data

Common/server:
 com.skycraft.atmosphere.weather.RegionalWeather
  kindOf(MinecraftServer,String regionId)
  kindAt(ServerLevel,BlockPos)
  windAt(ServerLevel,BlockPos) -- degrees in the existing yaw convention
  remaining(MinecraftServer,String regionId) -- ticks
  fronts(MinecraftServer) -- detached WeatherFront copies
  sampleFront(MinecraftServer,double x,double z) -- live selected front
 com.skycraft.atmosphere.weather.WeatherProfile.of(Region)
 com.skycraft.atmosphere.WeatherFront
  center/radius, velocity, WeatherKind, intensity, lifetime;
  intensityAt, rainBandAt and curtainDensityAt provide existing spatial weights.

Physical client only:
 com.skycraft.atmosphere.client.ClientWeather
  active(), kind(), profile(), region(), kindOf(String regionId)
  rain(), snow(), ash(), sand(), clouds(), fog(), wind()
  windDegrees(), windX(), windZ(), fronts(), sampleFront(double,double)
The scalar presentation values are eased weather weights, generally 0..1, not
physical precipitation rates or wind metres per second. Wind direction indicates
where wind travels: X=-sin(degrees), Z=cos(degrees). Region may be null before the
first update; kindOf may return null for an unknown region. active=false is a real
state, not permission to create an independent authoritative weather simulation.

WeatherPackets.Sync currently transmits full/delta regional entries and an
optional front list. Skycraft applies these to ClientWeather. External rendering
should consume that maintained state rather than decode skycraft:packet_N IDs.

Pure celestial/latitude helpers

com.skycraft.atmosphere.AtmosphereMath contains thread-safe pure helpers for
latitude, aurora elevation/strength, moonCycle, moonLight and nightSkyVisibility.
moonCycle takes clock ticks; moonLight takes solar angle in radians plus clock
ticks and the Secunda flag. MoonLight is an immutable direction/illumination
record. Its existing Masser/Secunda orbital relationship is shared gameplay/sky
input, not a claim that the new external visual implementation is already wired.
Package-private NightSkyState and renderer texture layouts are internal details.

Dungeon/interior data

com.skycraft.atmosphere.DungeonAir.Volume is immutable metadata from actual saved
dungeon pieces: x0/y0/z0 are minima, x1/y1/z1 are exclusive maxima, floor is a block
height, and style identifies the existing local atmosphere profile. The current
styles are 0 dust/mine/Dwemer, 1 ordinary underground, 2 ice/snow, 3 bioluminescent.
DungeonAir.Sync includes dimension and source chunk coordinates with at most 32
nearby volumes. It is server-derived metadata, not fog permitted under any roof.
The server index follows real chunk load/unload; sync never requests terrain.

Current client InteriorAtmosphere.profileAt(Vec3) returns -1 outside known volumes;
readyAt(Vec3) reports its own metadata/blend readiness. It is not a public bulk
volume/light snapshot provider. light/displace receive existing spell/impact
effects on the client thread. A new integration needing full dynamic emitters,
smoke or volume arrays should agree on an explicit snapshot adapter with the
owning developer; do not read its private collections or duplicate simulation.

Terrain and distant data

com.skycraft.tamriel.TamrielMap and MapSample are existing project contracts:
 sample(int x,int z,MapSample out), region(x,z), regionIndex(x,z), elevation(x,z).
Reuse one caller-owned MapSample per worker/thread. sampleScratch returns a
read-only borrowed per-thread object, overwritten by later sampling: copy needed
values before retaining a result or submitting work elsewhere.

MapSample exposes macro elevation, region/border blend, river/lake/coast distances,
water level, terrain roughness/crag/dunes/wetland/road strengths, slope, rainshadow,
geothermal heat and aspect. NaN waterLevel means no nearby authored water surface.
These are macro context values, not final block heights, collision, cave geometry,
settlement meshes or proof a native chunk exists. Roads and planned structures
can change the realized surface. Use actually loaded chunk/mesh data where exact
geometry, occlusion, shadows or capture readiness matters; do not force generation
from rendering or call ServerLevel services on generation/worker threads.

com.skycraft.bake.Bake.inputsHash() identifies the current map/plan/code inputs.
The landmass, roadplan, streetplan and sceneplan bakes are seed-independent plans;
their format/input hash must match before reuse. That hash is not an entire
world/session identity, final chunk data version, or a version for the external
mod's GPU cache. A distant cache needs its own schema plus the relevant plan hash,
world/session/dimension identity and source-data revision.

Native generation and world coverage

The normal generator remains native NoiseBasedChunkGenerator with Skycraft's
density/material/biome inputs. 26.3 compiles noise/density samplers for the current
world's seeded CompileContext; WorldNoise.bind is an internal bridge to that real
sampler. Do not retain a previous world's compiled sampler or registry holders.
Native TERRAIN combines noise, surface and carvers; old NOISE/SURFACE timings
are not equivalent stage boundaries. Macro elevation is not a final block result.

Copy bounded exact geometry from the appropriate native chunk stage on its
owning thread, then pass detached values to workers. Live neighboring chunk reads
outside the native generation region are invalid. Settlement Canvas/landmark
placement clips actual reads/writes; terrain-only fallback uses getBaseColumn
with the current generator/RandomState. That predicts terrain/fluid, not completed
settlements, trees, decorated caves or entity collision. Unknown terrain is not
empty air, and rendering must not add unbounded generation tickets each frame.

Current runtime geography is authored Tamriel, the fixed foreign lands and open
ocean beyond. Beyond.ENDLESS_LANDS_ENABLED is false. Dormant procedural tile
classes and old saved tile files remain for explicit tools/old data; they are
not active exterior land. Do not resurrect continents from a historical tile
cache. TamrielMap's older Javadoc about endless lands is not the current policy.

OceanWrap performs server-authoritative same-dimension travel at the distant
overworld seam. OceanWrapMath is pure rectangular-torus arithmetic: inclusive
negative/exclusive positive bounds, default half-width 29,360,128 blocks and
period twice that. Actual enable/bounds/arrival-buffer values are synced server
config, currently read internally by OceanWorldConfig. A new distant adapter
must expose actual configured values rather than hard-code the defaults. Wrapping
does not rewrite old chunks; realm dimensions do not inherit that seam. Discard
old-view far jobs/history when server travel replaces the camera position.

Capture/readiness integration

Existing capture checks distinguish loaded terrain, received lighting, queued
mesh work, completed main-camera frames, camera clearance and interior metadata.
Resident chunk tickets are not pending work. A new distant/terrain renderer must
provide truthful readiness for its own queues and visible GPU meshes; vanilla
terrain completion does not establish that a separate renderer has finished.
Agree on a bounded public observation adapter before accepting its captures:
current level/session/resource identity, pending generation/mesh/upload work,
visible mesh coverage and completed main-camera frame identity. Do not introduce
blocking GPU query reads or fixed sleeps as a substitute. This observation
adapter is an integration requirement, not an already implemented external API.

WorldReadiness is the existing harness, not a public cross-mod facade. It requires
FULL nearby client chunks, received lit columns, no propagation work, a completed
real ClientLevel.queueLightUpdate FIFO witness, idle terrain queues after the MAIN
world draw, stable completed frames, unchanged level/renderer/view, a collision-
clear camera and settled media/weather. Native ClientLevel.update drains that
FIFO after tick Post. The 38 correction consumes the completed witness before
renewing it; replacing it at every tick's start causes an indefinite wait. Empty
or occluded views still require completed main-frame evidence. Readiness uses a
bounded deadline and stops immediately when its actual conditions complete.

The preserved DH probe deliberately says "sampled data ready; GPU meshes
unverified". It cannot establish an external renderer's displayed coverage.
Require separate CPU-data, GPU-upload and completed-main-view revisions together
with exact pose, requested coverage and level/session/resource identity. Near
Sodium readiness, far-data presence and a finished GPU frame are separate claims.
Invalidate them for reconnect, travel, reload and relevant source changes. No new
external status provider is implemented or certified by this handoff.

Plan route/candidates, inspect loaded geometry, adjust obstructed views, then cache
the accepted pose with map/generation identity. Reuse it with quick clearance and
readiness checks until those inputs change. Keep atomic PNG/receipt publication
and real readiness flags; a plausible image cannot override a failing witness.
See VISUAL-TEST-CAMERAS.md and NATIVE-26.3-RENDER-HANDOFF.md for the existing frame
and pass ownership. External lighting/shader/distant-renderer ownership remains
separate from Skycraft's authoritative world generation and gameplay.

Network compatibility

SkyNetwork is the current native required-play-payload transport. WireProtocol
schema 3 includes the mod version and a hash of ordered message classes/directions.
Source 37 registers 124 payload types; always query the actual running catalogue.
Body-layout changes still require an explicit schema/version change. Do not append
external registrations after SkyNetwork.init or depend on numeric packet_N names.
A separate external protocol should own its own namespace/version and use native
payload registration, while reading Skycraft data through an agreed adapter.

Registry-bearing item/text codecs require the actual current connection/world
registry context. Explicit HolderLookup.Provider overloads are required for
background storage. ItemData's convenience resolver permits only current game
threads and never caches a world's registries. CustomData edits use update/set
transactions; reads do not expose its mutable underlying CompoundTag.

Both native server and client handlers run on their main threads. Real TCP tests
must prove a connected non-memory connection and retain matching endpoint protocol
receipts. SkyNetwork.diagnostics reports actual codec invocation counts only in
dev/autotest; registered types, negotiated types and exercised message bodies are
different coverage claims. Never certify the external integration from an
integrated-memory connection, a successful build or a screenshot file alone.

Native entity rendering caveat (confirmed after actual build38 NPC captures)

EntityRenderDispatcher treats every AvatarRenderState as a real avatar and
selects the player AvatarRenderer at submission. Custom NPC/humanoid renderers
must use an appropriate non-Avatar state, retaining their registered entityType.
Separately, NeoForge clears ContextKey entity data after extract/finalize and
then invokes RegisterRenderStateModifiersEvent callbacks. Custom entity
snapshots must be populated after that reset; a write at the end of extraction
or finalize still disappears. The existing core player modifiers are already
in that supported phase. LevelRenderState sky/cloud snapshots are separate.

An isolated native-compiled eight-file correction is documented at
dist/code-review/neoforge-migration/npc-render-fix/review.txt. It is UNAPPLIED
to shared source pending coordination with the other UI/rendering owner.
The complete durable source proposal and hash sidecar are under
tools/migration/patches/entity-render-state-263.unapplied.patch and .json.
It preserves public native64x64 mesh builders, inherited clothing overlays,
custom armor/features/costumes/poses and genuine player cosmetics/capes.
No new mixins, access transformers or copied rendering implementation are needed.
Full build, exact dispatcher/snapshot assertions and real NPC/creature/player
captures remain required after integration.
